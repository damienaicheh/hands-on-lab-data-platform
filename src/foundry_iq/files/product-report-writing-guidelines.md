# Contoso Product Report Writing Guidelines

These guidelines describe how to write clear, consistent reports about products in the Contoso catalog. Follow them whenever you document a product's characteristics, positioning, or lifecycle status.

## 1. Purpose and Audience

- State the purpose of the report in the first paragraph (launch review, quarterly
  update, discontinuation notice, etc.).
- Identify the intended audience (executives, product managers, sales enablement, or
  support teams) and adapt the level of technical detail accordingly.
- Keep executive summaries under 150 words; put supporting detail in later sections.

## 2. Required Sections

Every product report must include the following sections, in this order:

1. **Overview** — Product name, SKU, category, and a one-sentence description.
2. **Key Features** — Bullet list of the three to five most important capabilities.
3. **Target Segment** — Primary customer segment and typical use case.
4. **Lifecycle Status** — One of: `Concept`, `Beta`, `Generally Available`, `Mature`,
   or `Retired`.
5. **Pricing Tier** — Reference the current tier (`Essentials`, `Professional`,
   `Enterprise`) without quoting exact prices; prices live in the pricing sheet.
6. **Dependencies** — Related products or accessories required for full functionality.

Use the following summary table at the top of every product report so readers can scan
the key attributes at a glance:

| Attribute        | Example value          | Notes                                  |
| ---------------- | ---------------------- | -------------------------------------- |
| Product name     | Contoso AeroDesk 200   | Exactly as registered                  |
| SKU              | CT-1042-03             | Format `CT-XXXX-YY`                     |
| Category         | Workspace hardware     | From the catalog taxonomy              |
| Lifecycle status | Generally Available    | One of the five allowed statuses       |
| Pricing tier     | Professional           | Reference tier, not the exact price    |
| Last updated     | 2026-06-30             | ISO date `YYYY-MM-DD`                  |

## 3. Style and Tone

- Use plain, factual language. Avoid marketing superlatives such as "best-in-class".
- Write in the present tense for current products and the past tense for retired ones.
- Spell out an acronym on first use, then use the short form.
- Prefer short sentences and bullet lists over dense paragraphs.

## 4. Data and Evidence

- Every claim about a product capability must reference a source (spec sheet,
  engineering ticket, or validated test result).
- Round measurements consistently (for example, weight to one decimal place).
- Flag any figure that is an estimate with the label `(estimate)`.

## 5. Naming and Formatting Conventions

- Product names are written exactly as registered, including capitalization.
- SKUs use the format `CT-XXXX-YY` (category code, model number, revision).
- Dates use the ISO format `YYYY-MM-DD`.
- Use Markdown headings so reports can be indexed and searched consistently.

## 6. Review and Approval

- A product report is considered final only after review by the responsible product
  manager.
- Record the reviewer's name and the review date at the bottom of the document.
- Keep a short changelog of material revisions so readers can track updates.
